# Smart Placement Prediction System

An end-to-end **Machine Learning powered placement prediction and student management platform**, built as a final-year B.Tech Information Technology project. It combines a FastAPI + scikit-learn/XGBoost backend with a modern React dashboard to help a college placement cell predict a student's placement readiness, understand *why* the model predicted what it did, and get personalized, actionable recommendations.

---

## 1. Project Description

Placement cells traditionally rely on manual shortlisting and gut-feel judgments about which students are "placement ready." This system replaces that guesswork with a trained classification model that:

- Learns from historical student data (academics, test scores, skills, experience).
- Predicts whether a given student is likely to be **Placed** or **Not Placed**, along with a probability score.
- Explains **why** — which factors are helping and which are hurting the student's chances.
- Recommends **specific, personalized next steps** rather than generic advice.
- Gives the placement cell a dashboard to track department-wise placement rates, at-risk students, and overall trends.

---

## 2. Features

- 🎯 Real-time placement prediction with probability, readiness level, and explanation
- 🧠 Four ML models trained and compared automatically (Logistic Regression, Decision Tree, Random Forest, XGBoost) — best model auto-selected by F1 score
- 💡 Rule-based smart recommendation engine (9 distinct rules, never generic)
- 👥 Full student management (search, filter, sort, add, edit, delete)
- 📊 Dashboard with KPI cards and charts
- 📈 Analytics page: department comparison, internship/certification/project impact
- 🧪 Model Performance page: accuracy/precision/recall/F1 table, confusion matrix, feature importance, one-click retrain
- 🔐 Simple demo login
- ⚠️ Graceful error handling when the backend/model isn't available

---

## 3. Technology Stack

**Frontend:** React 18, Vite, React Router, Axios, Recharts, Lucide React icons, plain CSS (design-token based)

**Backend:** Python, FastAPI, Uvicorn, Pydantic

**ML:** Pandas, NumPy, scikit-learn (Logistic Regression, Decision Tree, Random Forest), XGBoost, Joblib

**Database:** SQLite (auto-created on first backend startup, auto-seeded from `dataset.csv`)

---

## 4. Project Architecture

```
React (Vite, :5173)  <--- Axios/HTTP/JSON --->  FastAPI (Uvicorn, :8000)  <--->  SQLite (placement.db)
                                                        |
                                                        v
                                          placement_model.pkl (joblib bundle:
                                          best model + encoders + scaler)
```

- `train_model.py` is a standalone script that generates the dataset (if missing), trains all four models, evaluates them, and saves the winning model + preprocessing pipeline as one joblib bundle.
- `model.py` loads that bundle once at backend startup and exposes `predict_student()`, used by both `/predict` and by student CRUD endpoints (so every stored student also gets a live prediction).
- `main.py` is the FastAPI app: it owns the SQLite database, seeds it from `dataset.csv` on first run, and exposes all REST endpoints.

## 6. Installation Instructions (Windows 11 + VS Code)

Prerequisites: Python 3.10+ and Node.js 18+ installed and on PATH.

Open the `Smart-Placement-Prediction` folder in VS Code, then open **two terminals** (one for backend, one for frontend).

## 7. Backend Setup

```powershell
cd backend
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
python train_model.py
uvicorn main:app --reload
```

This will:
1. Create and activate a virtual environment
2. Install FastAPI, scikit-learn, XGBoost, etc.
3. Generate `dataset.csv` (600 synthetic students) if it doesn't exist yet, train all 4 models, and save the best one as `placement_model.pkl`
4. Start the API server at **http://127.0.0.1:8000** (Swagger docs at **http://127.0.0.1:8000/docs**)

## 8. Frontend Setup

In a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

The dashboard will be available at **http://localhost:5173**.

> The backend must be running for the dashboard to load real data — if it isn't, every page shows a clear "backend unavailable" message instead of crashing.

## 9. Dataset Information

`dataset.csv` contains **600 synthetic student records** across 6 departments (Information Technology, Computer Science, Electronics and Communication, Electrical and Electronics, Mechanical, Civil). Placement outcomes are **not random** — they're generated from a weighted score of CGPA, coding score, aptitude, communication, attendance, internships, projects, certifications, backlogs (penalty), and extracurriculars, plus Gaussian noise, passed through a logistic function. This keeps the relationship between features and outcome realistic enough for the models to learn meaningful patterns, while still leaving room for edge cases.

Columns: `student_id, name, department, gender, tenth_percentage, twelfth_percentage, cgpa, backlogs, attendance, aptitude_score, coding_score, communication_score, technical_skills, certifications, internships, projects, extracurricular_activities, placement_status`

---

## 10. Machine Learning Workflow

1. **Load or generate** `dataset.csv`
2. **Preprocess:** label-encode `department` and `gender`; standard-scale all numeric features; label-encode the target (`Placed` / `Not Placed`)
3. **Split:** 80/20 train/test, stratified on the target
4. **Train four models:** Logistic Regression, Decision Tree, Random Forest, XGBoost
5. **Evaluate each** on Accuracy, Precision, Recall, F1-score, and a Confusion Matrix
6. **Select the best model** by F1-score (a balanced metric for a moderately imbalanced classification task)
7. **Extract feature importance** (native `feature_importances_` for tree models, absolute coefficients for Logistic Regression)
8. **Persist everything** — the model, encoders, scaler, target encoder, and feature importance — as a single `joblib` bundle (`placement_model.pkl`), so a single file is enough to serve predictions consistently with training-time preprocessing.

Re-run training anytime with `python train_model.py`, or from the UI via the **Model Performance → Retrain Model** button (which calls `POST /train-model`).

## 11. API Documentation

Base URL: `http://127.0.0.1:8000`

| Method | Endpoint | Description |
|---|---|---|
| GET | `/` | API info + model status |
| GET | `/health` | Health check |
| POST | `/predict` | Predict placement for a student profile (not persisted) |
| GET | `/students` | List students — supports `department`, `placement_status`, `search`, `sort_by`, `order` query params |
| GET | `/students/{student_id}` | Get one student |
| POST | `/students` | Create a student (auto-predicted + stored) |
| PUT | `/students/{student_id}` | Update a student |
| DELETE | `/students/{student_id}` | Delete a student |
| GET | `/analytics` | Aggregate dashboard/analytics data |
| GET | `/model-performance` | Metrics for all trained models + feature importance |
| POST | `/train-model` | Re-run `train_model.py` and hot-reload the model |

Full interactive documentation (with request/response schemas) is auto-generated by FastAPI at **`/docs`**.

## 16. Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError` when running backend | Make sure the venv is activated (`.\venv\Scripts\activate`) and `pip install -r requirements.txt` completed successfully |
| Frontend shows "Could not reach the backend" | Confirm `uvicorn main:app --reload` is running and reachable at `http://127.0.0.1:8000/health` |
| `/predict` returns 503 | The model hasn't been trained yet — run `python train_model.py`, or hit **Retrain Model** in the UI |
| `xgboost` fails to install on Windows | Upgrade pip first: `python -m pip install --upgrade pip`, then retry; as a fallback the app still works with the other 3 models if XGBoost is unavailable |
| Port 8000 or 5173 already in use | Stop the other process, or run `uvicorn main:app --reload --port 8001` / `npm run dev -- --port 5174` and update `API_BASE_URL` in `frontend/src/services/api.js` accordingly |
| CORS errors in browser console | Confirm the backend's CORS middleware is active (it is, by default, for all origins) and that you're calling `http://127.0.0.1:8000`, not a mismatched host/port |

## 18. AWS Deployment (Future Steps)

1. **Backend:** Containerize with Docker, push to Amazon ECR, deploy on **AWS App Runner** or **ECS Fargate**; store `placement_model.pkl` in the image or pull it from **S3** at container startup.
2. **Database:** Migrate SQLite → **Amazon RDS (PostgreSQL)** for a multi-user production deployment.
3. **Frontend:** Run `npm run build` and host the static `dist/` output on **Amazon S3 + CloudFront** for a fast, cached global delivery.
4. **Environment config:** Move the hardcoded `API_BASE_URL` in `frontend/src/services/api.js` to a build-time environment variable (e.g. `VITE_API_BASE_URL`) so the same build can point at different backends per environment.
5. **CI/CD:** Use **GitHub Actions** to run tests, build the Docker image, and deploy on every push to `main`.
6. **Secrets:** Store DB credentials and any future auth secrets in **AWS Secrets Manager**, not in source control.
7. **Monitoring:** Enable **CloudWatch** logs/metrics for the backend service and set up basic alerting on error rates.
